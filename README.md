# Music Cue Sheet and Rights Clearance Gate

A Python and SQLite rights-clearance gate for television music cue sheets:
it reconciles every music cue an episode uses against the license record
that is supposed to cover it (library, usage type, term, territory, media
type, performing rights organization), refuses to produce a cue sheet for
any episode with even one uncovered cue, names the exact cue and the exact
reason, and exports the standard ASCAP/BMI cue sheet form with `openpyxl`
for every episode that clears the gate. Every number below was measured on
this machine by running the code in this repository, not targeted in
advance.

## Why this exists

A music cue sheet is the document a PRO (ASCAP, BMI) pays royalties
against; a cue sheet that lists a cue the production never actually
cleared is not a paperwork error, it is an unlicensed use with a paper
trail attached to it. The failure this project is built to catch is the
one that actually causes a claim: a cue airs on a date, in a territory, on
a media type, that the underlying license does not actually cover, and
nobody catches it because the cue sheet got built from the music log
without ever being checked against the license table. This project is the
smallest honest version of that check: a real reconciliation against a
real license table, a real refusal that names names, and a real exported
cue sheet, never produced for an episode that did not clear.

## What this is and is not

- **The dataset is synthetic and says so.** 60 episodes of a fictional
  television program ("Harborline"), 27 license records across 6 invented
  music libraries and 4 usage types, 10 invented composer/publisher pairs,
  240 music events total. No claim on this page implies a real production
  cleared real music; every name, date and cue title here was generated by
  `cue_sheet_gate/generator.py` from a fixed seed (`20260801`), and the
  generator verifies its own output against the independent oracle below
  before it is allowed to call a construction "clean" or "a defect of
  reason X" (see Findings for why that verification step exists).
- **License coverage is a containment relation, not equality.** A "World"
  territory license covers a "United States" air; a "United States"
  license does not cover a "World" air. Same shape for media type
  ("Broadcast Television" < "Broadcast and Streaming" < "All Media"). This
  is deliberate: a real cue sheet error is far more often "the license was
  narrower than the use" than "the two fields were spelled differently."
- **Six fixed reason codes, not free text.** Every refusal names one of:
  `no license record found`, `license expired before air date`, `license
  not yet effective on air date`, `wrong territory`, `wrong media type`,
  `performing-rights organization mismatch`. A gate that explained itself
  in prose would be unauditable; a gate that always picks from six named
  reasons is something a rights administrator can act on without reading
  code.
- **The gate refuses, it does not warn.** `gate_episode` returns a typed
  `Refused` result object naming every violation; `gate_episode_or_raise`
  raises `GateRefusedError` for a caller that wants a hard stop instead
  of a result to branch on. Neither path produces a normal cue sheet for
  a refused episode; `export_cue_sheet` still writes a workbook for a
  refused episode, but it is a one-page placeholder titled "CUE SHEET
  REFUSED, NOT FOR DISTRIBUTION" naming the same violations, never the
  real 12-column form.
- **12 named fields, chosen to match what an ASCAP or BMI cue sheet
  actually asks for** (program, episode, air date, then per cue: title,
  composer, publisher, PRO, usage type, duration, in-cue timecode, out-cue
  timecode, and the composer/publisher share split). See Architecture for
  the exact list.
- **Machine and toolchain.** 8 physical / 16 logical cores, Windows 11
  Home, Python 3.12.10, openpyxl 3.1.5, pytest 9.1.1, SQLite (stdlib
  `sqlite3`).

  generator.py            synthetic dataset builder: 60 episodes, 20 with 2 seeded defects each (40

### Why territory and media type are containment relations, computed from a rank table, not a lookup table of allowed pairs

`_TERRITORY_RANK` and `_MEDIA_RANK` give each value an integer; a license
covers a request when its rank is greater than or equal to the request's
rank. This is 6 lines of code instead of a hardcoded table of which
license territory covers which event territory, and it is also exactly
the kind of code that is easy to get backwards (does the license's rank
need to be `>=` or `<=` the event's rank). That is precisely why the
independent oracle recomputes the same containment with a different data
structure (a list scanned front to back, stopping at the first match)
rather than importing this rank table: a sign error here would not be
caught by a test that also imports the broken table.

### Why the reconciliation engine is indexed and the oracle is not

`reconcile.py` builds a `dict[(library, usage_type), list[LicenseRecord]]`
once and looks up each event's small candidate list directly.
`oracle.py` scans the full license table for every single event, with no
index and no early-exit shortcuts beyond "stop at the first fully
covering record." At this dataset's scale (240 events, 27 licenses) the
difference is not a performance story worth measuring; the point, per
BUILDER.md's reference-oracle pattern, is correctness: an indexing bug in
the dict-based lookup (wrong key, stale index, a candidate silently
dropped) would show up as a disagreement against the oracle, because the
oracle never builds or trusts that index. `test_oracle_diff.py` and
`scripts/run_oracle_diff.py` are the two places that check this.

### Why a refused episode still gets a workbook, just not a cue sheet

An early design skipped export entirely for a refused episode. The
workbook for episode 47 simply would not exist while 59 others did, which
looks exactly like a tooling bug ("why didn't episode 47 export?") to
anyone who did not already know it was refused. Writing a one-page
placeholder titled "CUE SHEET REFUSED, NOT FOR DISTRIBUTION," naming the
same cues and reasons the gate reported, makes the refusal visible at the
point someone would actually look for the missing file, not just in a log
they may not have read.

### The 12 required cue sheet fields

`Program/Series Title`, `Episode Title/Number`, `Air Date`, `Cue Title`,
`Composer`, `Publisher`, `Performing Rights Organization (PRO)`, `Usage
Type`, `Duration (Timing)`, `In-Cue Timecode`, `Out-Cue Timecode`,
`Composer/Publisher Share (%)`. These follow the substance of ASCAP's and
BMI's cue sheet guidance: identify the program and episode, the air date,
then per cue the title, the writer and publisher, the PRO that will pay
on it, how the music was used, how long it ran, where it started and
ended, and how the royalty splits between composer and publisher. The
exact column order is asserted in `export.CUE_SHEET_COLUMNS` and pinned by
`test_export.py::test_cue_sheet_has_exactly_12_named_fields`.

## Validation

```
$ pytest tests -v
```

32 passed. Full output in `docs/test_output.txt`. Layers specific to the
claims on this page:

1. **Exact set match, not just a count.** `test_40_of_40_seeded_defects_caught_naming_cue_and_reason`
   asserts the gate's findings equal the generator's seeded set exactly
   (`caught == expected`, each element an `(episode_id, cue_title,
   reason)` tuple), so a gate that flagged the wrong 40 cues out of 240,
   or named the right cue with the wrong reason, would fail even though
   the count matched.
2. **Independent oracle, diffed exactly.** `test_oracle_diff.py` compares
   `reconcile.py`'s indexed engine against `oracle.py`'s brute-force scan
   on every one of the 240 synthetic events and asserts 0 mismatches.
   `oracle.py` never imports `reconcile.py`.
3. **The gate's own construction is self-checked.** `generator.py` calls
   the oracle on every event it builds, before writing it to the
   database, and raises `GeneratorInvariantError` if a "clean" event does
   not come back covered, or a "defect" event does not come back refused
   for the exact intended reason. The 40/40 and 0/40 numbers below cannot
   be an artifact of the generator and the gate quietly agreeing by
   construction, because the oracle that checks the generator's work is
   the one piece of code in this repository that is never shared with
   `reconcile.py`.
4. **Both the result-object and the raise path.** `test_gate_scale.py`
   exercises `gate_episode` (returns `Refused`) and
   `gate_episode_or_raise` (raises `GateRefusedError`) against the same
   refused episode and the same passed episode, so neither entry point is
   a decoration over a check the other one skips.

## Findings

**A defect's "bad date" must be computed against the exact same license
the defect event will use, not a second independent random pick.** The
first version of `_make_defect_event` for `LICENSE_EXPIRED` picked a
license in the caller (`build_dataset`) to compute a date past its term
end, then called `_make_defect_event`, which picked its *own* random
license from the same pool to build the actual event. The discriminating
measurement: the very first synthetic episode generated failed its own
oracle self-check with `covered=True`, immediately on the first run,
because the event's second random pick landed on a different license
whose term happened to cover the "expired" date computed against the
first one. The fix was structural, not a tweak: `build_dataset` now picks
the license once, passes it into `_make_defect_event` as `forced_license`
for both date-boundary reasons, and the function raises
`GeneratorInvariantError` if `forced_license` is missing rather than
silently falling back to a second random choice. This is exactly the kind
of bug a reference oracle exists to catch, and it was caught before a
single number in this README was ever measured, by the same oracle call
that now runs inside the generator on every build.

**Restricting defect construction to "single-license" keys was too
narrow, and failed loudly instead of silently.** `WRONG_TERRITORY`,
`WRONG_MEDIA_TYPE` and `PRO_MISMATCH` defects were first built only from
the 21 (library, usage_type) keys with exactly one license record,
reasoning that a key with two records (a renewal) could let a corrupted
event accidentally match the other record. Generating the actual dataset
raised `GeneratorInvariantError: no single-record-key license admitted a
'wrong media type' defect` on a specific date, because every single-record
license active on that date already had the broadest media type ("All
Media"), leaving no "one step narrower" media type to corrupt into a
defect. The fix: the restriction was unnecessary in the first place,
because a key's two license records (where they exist) never overlap in
term by construction, so at most one of them can ever cover a given date;
the candidate pool for these three reasons was widened to every license
covering the date, single-record or not, and the actual ambiguity this
was guarding against never existed for the right reason, only for the
reason (date-boundary defects) that the `forced_license` fix above already
covers.

## Limitations

- Each episode carries exactly 4 music events in the synthetic dataset; a
  real episode's music log can run much longer, and nothing in this
  repository's measured numbers speaks to performance at that scale (the
  design of the indexed engine would, but it was not benchmarked here,
  see "Why the reconciliation engine is indexed" above for why this
  dataset's size made that a correctness question, not a speed one).
- Territory and media type containment are modeled as a single linear
  rank per dimension (narrowest to broadest). A real license portfolio
  can have genuinely incomparable territories (for example, "United
  Kingdom" and "Germany," neither contained in the other short of
  "World"), which this model does not represent; it only models nested
  broadening, not disjoint regional splits.
- The six reason codes are reported in a fixed priority order (term,
  territory, media, PRO) when multiple candidates fail in different ways;
  a cue that is simultaneously wrong on two dimensions against its one
  real candidate license is reported with the first reason in that order,
  not all of them.
- The share-percentage field is exported as a formatted string
  (`"56.7% / 43.3%"`), not two separate numeric cells; a cue sheet
  consumer that wants to recompute splits programmatically from the
  exported workbook would need to parse that string back apart.
- The reserved "no license at all" scenario uses one fixed,
  never-licensed (library, usage_type) key; a real catalog could have the
  no-license case arise from any combination, not a dedicated one.
